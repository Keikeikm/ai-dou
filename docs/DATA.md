# 数据中心与训练数据（v1）

从首页进入 `/analytics`。默认分析吹牛的已完成对局；可切换斗地主、玩家、开局日期和完成状态。AVA 在浏览器本地进行图表推荐、分布分析与显著性检测，不额外调用 LLM。原有斗地主的单局分析仍可从“回放与日志”主动打开；牌桌不会自动嵌入分析面板。

## 保存与身份

正常启动 `npm run ui` / `npm start` 时，数据保存在 `data/ai-dou.sqlite`，可用 `SCORE_DB_PATH` 指定位置。`data_profiles`、`data_episodes`、`data_participants` 与原有结算表共存。每个已接受动作都会保存；完成、换局、离开和服务关闭均会归档。突然终止后，已提交的 active 记录会在下次启动时标记 interrupted。无动作的空房间不算数据。浏览器关页不等于主动结束房间，仍可能等到房间过期或服务关闭才归档。

服务按单机单实例设计；数据库会阻止第二个存活的服务实例接管同一个文件，以免把进行中牌局误归档。需要多个服务时分别设置 SCORE_DB_PATH。测试默认内存数据库，数据中心会明确提示非持久模式。数据库不会自动删除历史；备份应在服务关闭后复制数据库，运行期间请使用 SQLite 的备份机制，不能仅复制主文件而忽略 WAL。

真人默认使用 `human_local`。可创建多个本机玩家档案，同名档案不会合并；开局选择一份档案后，本房间所有新局保持该身份。不同浏览器在同一服务上默认共用默认档案，多人轮流使用时请各自选择。档案不是登录账户，也不是身份验证，目前不新增联机多人功能。AI 的身份根据类型、显示名、席位、模型名称和策略名称生成；每步另保留已有策略版本/digest（若有）。后续可增加联网账户到 profileId 的映射。

旧版已结算的斗地主日志会在启动时自动导入，保留旧玩家 ID，标记 `identity: legacy` / `imported: true`。旧记录没有开局时间时使用原结算时间；无法确认归属时不会按名字合并。旧版吹牛仅存于内存，已丢失的历史无法补回。

## 统计口径

- 日期按北京时间的开局日期分组。日期图只展示有样本的日期，不补造对局。
- 胜率 = 获胜的完成局 / 完成局。未完成局的 won 为 null，不能当作失败。斗地主可按地主、农民分别看胜率。
- 吹牛率 = 含至少一张假牌的出牌次数 / 出牌次数；此指标来自归档后的真值。
- 质疑率 = 质疑次数 / 回应次数；质疑成功率 = 抓到假牌次数 / 质疑次数。
- 斗地主不出率 = 不出次数 /（出牌次数 + 不出次数）；炸弹率 =（炸弹 + 火箭）/ 出牌次数。
- 描述统计保留系统兜底，但单独显示 fallback 数；“真人操作”不含兜底。少于 20 局的“积累中”只是样本提醒，并不是统计置信阈值。
- 分母为 0 显示 —。趋势、显著性与占比不应解读为因果、人格或策略优劣。筛选某个玩家会选择含该玩家的对局，主要图表只统计他的动作；风格表按玩家分别统计。

## 本机接口

接口限 `localhost` / `127.0.0.1` 同源，不是可直接部署到公网的多用户授权方案。

- `GET /api/data/overview?game=bluff&status=finished&profileId=...&from=...&to=...&limit=12&offset=0`
- `GET /api/data/profiles`，`POST /api/data/profiles`，JSON `{ "name": "小林" }`
- `GET /api/data/episodes/:id`：已归档原始数据与可重建快照。
- `GET /api/data/export?format=episodes|transitions`：流式 JSONL。接受相同 game/status/profileId/from/to 筛选，不受界面分页限制。

from/to 是开局时间的 Unix 毫秒（闭区间）。进行中的记录只能内部写入，不开放详情和训练导出，避免旁路读取隐藏牌。只有已归档的数据可分析。

## 完整档案 episodes

每行是一个 `StoredEpisode`，`schemaVersion: 1`。含游戏/规则版本、局 ID、房间/代次、时间、状态、玩家稳定 ID/类型/模型/统计，以及 `raw`：

- 斗地主：seed、玩家、完整合法动作日志及有限模型元数据（耗时、用量、策略等）。
- 吹牛：两人的初始手牌与全部已提交动作，包含 seat、source、at、durationMs。覆盖牌堆、声明、翻牌、输赢均可使用相同规则版本重建。

档案包含完整隐藏真值，供重建环境和校验使用；不要把整行 raw 直接当作策略模型的观测。模型自然语言回复、HTTP 详情、API key 与席位 token 不写入数据中心档案。原版斗地主单局日志由原结算功能继续管理。

## 决策样本 transitions

吹牛规则独立版本化：`bluff-sequential-52-v1` 为回应者始终出下一手，`bluff-winner-leads-52-v2` 为质疑赢家出下一手。旧档案缺少 raw.rulesVersion 时按 v1 还原；新牌局显式保存 v2。翻牌确认只控制展示推进，不作为游戏动作或训练样本。训练时应按 rules_version 分组，避免混用行动顺序不同的环境。

每行对应一个已接受的环境动作。筛选 profileId 时只输出该玩家的动作，但重建时仍会执行其他人的动作。

- `schema_version`、`game`、`rules_version`、`episode_id`、`step`：格式、规则与顺序。
- `actor_id`、`actor_name`、`actor_seat`、`policy`：身份和模型/策略。
- `behavior_source`：human / model / bot / http / fallback / unknown。`imitation_eligible` 仅为 human 或 model；按目标玩家进一步筛选，绝不能把兜底动作当作其风格。
- `observation`：行动者在动作前可见的信息。没有 seed、对方手牌或未揭开的牌。吹牛公开历史与游戏模型一致，仅最近 60 步；完整行为历史保留在 episodes。
- `action`：规则引擎实际接受的动作。斗地主出牌是 Card 对象数组，吹牛是卡牌 ID 数组；按 game/rules_version 使用对应适配器。
- `next_observation`：同一行动者在这个环境动作之后的观测；`next_observation_timing: after_one_environment_action`。它不是“该玩家下次决策时”的观测；斗地主的 current_actor 表示实际轮到谁。训练算法若需每人决策间隔转移，必须把中间对手动作折叠，不能把当前文件直接当作单智能体 MDP。
- `terminated`：只有完整对局的最后一个环境动作为 true；`truncated`：未完成档案的最后一个环境动作为 true。
- `reward`：中间动作 0；完整终局当前行动者胜 +1 / 负 -1；截断结尾 null。`reward_by_seat` 在终局给各席位收益，斗地主按阵营判定。它是初始训练约定，不是积分结算额，可从完整档案重算。
- `outcome`：该行动者最终胜负标签，未完成局为 null；属于监督标签，不能放进 observation。
- `timestamp`：动作接受时间；旧记录缺失则 null。动作耗时不是纯推理时间，不能跨来源直接比较。
- `split`：按 episode_id 的 SHA-256 哈希取模，约 80% train、10% validation、10% test，同一局不会跨集合。这是可重复的起点，不保证按玩家、时间或相同牌局种子隔离；正式实验应结合评估目标重划分并检查重复样本。

每步还原由服务端规则引擎完成，前端不能上传任意训练动作。第一版只提供数据采集、批量分析与导出；不包含强化学习训练器、模型部署或风格克隆结果。后续训练应固定规则版本，并结合目标玩家、有效来源、完整性和对手分布选择数据。
