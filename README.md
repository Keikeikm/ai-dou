# AI DOU

支持三个 AI Agent 自动对战观战，也支持 1 位真人与 2 位 AI 同桌斗地主。观战默认展开当前行动方手牌，其他席位可自行翻牌；真人对局期间只展开自己的手牌，对手牌不可点击翻开。

当前界面仅以 PC 桌面窗口为适配目标，推荐可用内容区 1280 × 720 或更大，最低布局尺寸为 900 × 540。更小的窗口保留桌面布局并允许滚动，不切换为手机单列牌桌或底部抽屉；移动端适配暂不在开发范围内。目前运行载体仍是 React 网页，尚未加入可安装桌面客户端的封装。

界面排印使用本地提供的开源字体：站酷快乐体用于游戏入口、玩家名和胜负提示，霞鹜文楷用于中文正文，Nunito 用于英文与数字。中文字体按字符分片加载，不依赖外部字体 CDN；倒计时和积分使用等宽数字，牌面保留扑克牌字形。字体均按 SIL OFL 1.1 授权，版权与许可随 `client/public/FONT-LICENSES.txt` 一并发布。

## 本地运行

需要 Node.js 22.13 或更新版本（使用内置 SQLite）。

```powershell
npm ci
npm run ui
```

开发时可用 `npm run dev` 自动重启服务。开发服务默认使用 5173；若已占用，会依次尝试后续端口，请打开终端打印的实际地址。Vite 热更新共用网页端口，无需单独占用 24678。显式设置 `PORT` 或使用生产模式时，端口被占用会报错，不自动更换。

打开 http://127.0.0.1:5173 。游戏大厅提供「三位 DeepSeek 建房」「三位 Bot 建房」，「自定义开局」可设置基础分或「新建空房」，不会自动创建或播放默认牌局。进入独立房间后点击「开始观战」启动服务端实时对局；设置、分享、密钥与入座收进右上角「设置」，历史及模型回复在底部「出牌记录 / 模型返回」抽屉中查看。「回放与日志」包含倍速、单步、日志导出与历次结算查询；结束后显示胜负、倍数和积分变化。

前端使用 React、TypeScript 和 Vite，按大厅、牌桌、观战控制、详情抽屉拆分组件及样式。服务端逐步调度，通过 SSE 推送实时快照；本地定时器只播放已收到的快照，不推进真实游戏。规则校验始终在服务端执行。每间房都有独立的对局、观众连接和日志，没有账户体系。

## 创建与观战

- 首页没有默认房间、发牌或对局订阅；访问首页不会调用模型。
- 「三位 Bot 建房」创建一间已入座三个内置 Agent 的新房，立即跳转到其独立观战地址。
- 「三位 DeepSeek 建房」准备三名独立模型席位，但不自动开局或调用模型；可用服务端共享 key，也可入座后逐席位配置。
- 「我来打 · 两位 DeepSeek / 两位 Bot」创建一位真人和两位 AI；真人默认在底部Claude大小姐席位，点击「开始对局」后操作。Bot 无需 key、无 API 费用，DeepSeek 需要已配置密钥。
- 「新建空房」进入等待入座状态，按名称和随机/贪心策略逐个添加 Agent；满三人后才发牌并允许开始。
- 「观战链接」可以复制给同机的其他浏览器标签，每个链接只订阅自己的房间状态。服务仍只绑定本机，不能直接跨设备访问。
- 「关闭房间」取消未完成决策并释放实时连接，短暂保留日志以供导出；关闭后的房间不可恢复。

每次建房和「随机新局 / 随机再来一局」都由服务端重新随机洗牌，保留房间号、Agent ID、密钥和基础分，不自动开始。观战页面不显示或提供种子设置，也没有同牌重开的入口；内部日志仍保留必要的重放信息。这些新局操作会生成新的计分对局，旧结算仍保留；刷新和历史回放只查看原局，不重新发牌或计分。

房间 API、退出策略和回收规则见 [房间系统说明](docs/ROOMS.md)。第六章已支持外部 HTTP Agent 与内置 Bot 混合入座，协议、密钥管理、地址放行和完整验收步骤见 [Agent API 说明](docs/AGENT_API.md)。

## 真人与 AI 对战

首页选择「我来打」，发牌动画结束后点击「开始对局」。叫分时选择不叫或 1–3 分；出牌时点击自己的多张牌组合选中，再点「出牌」，也可「不出 / 取消选择」。支持规则内核已有的对子、三带二、顺子、炸弹等牌型；非法选牌明确报错、保留选择，允许纠正，不会静默代打。AI 自动接续，真人每回合默认有 60 秒，超时才按系统托管处理并标记来源。历史回看时不能出牌，需要先「返回实时」。

每房最多一位真人，空房可选择「真人玩家（自己）」入座。操控令牌只在首次入座响应返回，保存于当前标签的 sessionStorage；同标签刷新及随机新局保留操控权，分享链接不含令牌。关闭标签、清空存储或后端重启后不提供操控权恢复；请重新建房。新房不会自动调用 DeepSeek，真人回合不调用模型，AI 仍各自只收到自己的手牌和公开信息。

这是本机 MVP，不是带账户和防作弊权限的联网游戏：普通观战接口、日志仍包含全手牌，真人界面盖住对手牌不代表服务端隐藏。房间暂停/新局等原有管理操作仍由本地同房使用者共享。操作协议、安全边界与验收步骤见 [真人对战说明](docs/HUMAN_PLAY.md)。真人模式最低布局为 900 × 680，推荐 1280 × 720 或更大。

牌桌采用深绿织纹桌布、厚金木椭圆桌沿与三角座位布局，桌面 HUD 集中显示阶段、底分、倍数和底牌，中心突出当前出牌和行动反馈。支持范围内的牌桌与游戏操作栏固定在一屏内，短高 PC 窗口使用紧凑布局，但不改变三角席位结构。手牌及长牌型通过纯 CSS 重叠网格按可用宽度换行，不在渲染时测量牌宽。三位角色使用用户提供的 Q 版 PNG：GPT大人是白发龙娘、Claude大小姐是橙发少女、鲸鱼娘是蓝发女仆；统一头像框完整展示素材，不额外裁掉角、翅膀或裙摆。素材保存在 `client/public/avatars/`，公开分发前应确认使用授权。角色与席位绑定，新房可选内置 Bot、DeepSeek 或外部 HTTP Agent；角色名称不是模型名称。

行动方切换、决策通知和「不出」不会重建整排卡牌；没有变化的 SSE 数据保留对象引用，倒计时只更新独立组件。固定高度的手牌托盘不会随牌数改变而挤动其他区域；实时连续出牌只播放一次短暂入场动画，重复通知、历史跳转和页面初始化不重复播放。

AI 观战默认展开三位玩家的手牌，无需翻牌。点击非行动方的手牌区域仍可盖住或翻开，支持键盘 Enter / 空格；当前行动方自动展开，本局内保留观众的手动选择。新局、切换房间或刷新页面恢复全部展开。真人对战仍只显示自己的手牌。翻牌只是当前观众的本地显示选择，不修改服务端游戏状态、不发送模型请求，也不影响其他观众。模型与 HTTP Agent 仍只接收自己的手牌、其他席位的剩余张数、已公开底牌和公开历史。

房间首次发牌和新代次显示洗牌、逐张发牌动画；动画只展示服务端已生成的手牌，不影响对局状态或产生额外模型调用。页面在当前标签的 sessionStorage 记录已展示的房间代次，刷新同一局不重复播放洗牌；存储不可用时退回本地展示，不影响真实发牌。动画在本地结束后启用开局控件；实时牌局若已推进则立即取消，减少动态效果偏好下跳过动画，历史/归档回看不重复洗牌。席位、当前动作和历史步骤明确标记模型、Bot、HTTP 或系统托管，托管不会冒充模型成功决策；累计统计只计已执行动作，不是付费请求统计。

每步 DeepSeek 回复可在底部「出牌记录」选中步骤后展开「DeepSeek 回复 · 当前步」，或直接打开「模型返回」抽屉查看，包括回复正文、请求 ID、token 数及实际执行动作；已完成对局随日志归档。详见 [DeepSeek 回复记录说明](docs/DEEPSEEK.md)。

DeepSeek 支持短策略 skill：三席位默认分别采用稳健结构、控场进攻、协作均衡风格，空房入座时可自行选择。每回合固定规则与 skill 前缀后携带自己的手牌、精简公开历史、服务端局势摘要和合法候选；不额外调用模型读取 skill，不引入 sub-agent。「模型返回」展示策略版本/指纹、供应商报告的缓存命中/未命中 token，以及本局有效统计覆盖数与加权命中率。缺失值不视为零，统计不等于账单。策略文件、缓存语义与配置见 [DeepSeek 接入](docs/DEEPSEEK.md)。

修改后端代码后需停止旧服务并重新运行 `npm run ui`；仅刷新网页只更新前端文件，不更新运行中的 Node 后端。首页及新局操作会检查后端能力，旧服务将明确提示重启，不再悄悄建立固定牌局。

## 外部 Agent 本地演示

已支持直接添加 DeepSeek 模型席位，不必另起代理。将 `.env.example` 复制成 `.env` 或 `.env.local` 并在本机填写 key（已有 `.env` 无需改名），启动服务后「新建空房」选择「DeepSeek 模型」即可。配置优先级为已有进程环境变量 > `.env.local` > `.env`。默认使用官方当前模型 `deepseek-flash`；未配置 key 可以先入座，但不能开局。真实对局会消耗 API 额度，回放不会调用模型。配置、密钥保护、模型选择及验收见 [DeepSeek 接入](docs/DEEPSEEK.md)。

「设置」只查询当前服务配置，不消耗额度，也不把「已配置」当作「已连接」。开局前可在密钥管理中选择席位并确认执行一次连接测试，使用固定模拟手牌，不推进真实牌局或计分，显示连接结果与耗时。测试和真实对局均可能产生 API 费用，均需用户主动操作；三个席位即使用同一个 key，手牌与每回合请求仍独立。更新代码/环境配置后请正常重启服务（先处理现有对局），页面提交的席位 key 仅存内存，重启后需重新设置。

先在另一个终端启动示例端点：

```powershell
$env:AGENT_API_KEY = 'ai-dou-local-demo'
npm run agent:example
```

随后启动棋牌室（如已启动，请先停止旧进程）：

```powershell
$env:AGENT_ALLOWED_ORIGINS = 'http://127.0.0.1:8787'
npm run ui
```

新建空房，选择「外部 HTTP Agent」，填写 `http://127.0.0.1:8787/decide` 和上述演示密钥，按不同名称加入三名 Agent 后开始观战。也可混合内置 Bot。默认不放行外部地址；公网 Agent 必须使用明确放行的 HTTPS origin。密钥只保存在服务端内存，接口和日志不回显，页面允许开局前替换或清除。

更换端口或调度配置：

```powershell
$env:PORT = '5174'
$env:TURN_TIMEOUT_MS = '1500'
$env:STEP_INTERVAL_MS = '950'
$env:ROOM_IDLE_TIMEOUT_MS = '1800000'
$env:ROOM_CLOSED_RETENTION_MS = '300000'
npm run ui
```

## 积分与结算

基础分默认 1，建房时可输入。总倍数为最终叫分 × 每个普通炸弹/王炸的 2 倍 × 春天/反春天的 2 倍；地主两份，农民各一份，三人积分变化之和为 0。积分按 Agent ID 累计，没有账户或排行榜，也不是现金筹码。

`npm run ui` 默认使用 `data/ai-dou.sqlite` 保存完整终局日志与积分流水；`BASE_SCORE` 配置默认基础分，`SCORE_DB_PATH` 配置数据库位置。同房重置不会删除旧局，已入账记录在房间回收和服务重启后仍可查询。活跃房间、未结束牌局和 Agent 密钥仍只在内存中。

详细公式、查询接口、事务与恢复策略见 [积分与结算说明](docs/SCORING.md)。数据库目录应独立保管，不提交到 Git。

## 观战与回放

底部「复盘分析」（也可从「回放与日志」打开）集成 AntV AVA 数据统计、图表推荐与自动洞察。可按玩家和历史步骤范围分析剩余手牌、动作/牌型分布、模型耗时、Token 和缓存命中率，点击图表或数据表跳回历史步骤，导出筛选数据 CSV。当前房间与归档回放均可使用，本地统计不调用模型。「向数据提问」支持用服务端 DeepSeek 结合真实对局和 AVA 结果进行连续问答、引用步骤及建议图表；仅发送时调用模型并可能产生费用，不推进对局。数据口径、配置与统计限制见 [AVA 复盘分析](docs/AVA_ANALYSIS.md)。

支持出牌动画、服务端真实思考倒计时和可筛选的牌局历史。历史按需打开为右侧抽屉；默认不占据牌桌，保留深绿金木桌沿与 Q 版角色风格。

「从头回放」或终局「回放本局」仅播放当前观众缓存的快照，支持 0.5×、1×、2×、4×、暂停、历史跳转及单步；实时对局仍可继续运行，不会抢走回看位置。「返回实时」重新跟随最新快照。实时模式的「暂停对局 / 继续对局 / 推进对局一步」才会影响本房服务端调度。只有显式「再来一局 / 开启新局」会生成新的计分对局。

结算记录中的「回放此局」打开 `/games/:gameId`，即使原房间已回收或服务重启，也能只读回放已保存对局，不调用 Agent 或重复计分。完整语义、时间字段与验收步骤见 [观战体验说明](docs/SPECTATING.md)。

## 调度与异常处理

- 状态：等待开始 → 运行 / 暂停 → 对局结束；停止后的调度器不可恢复。
- 每次只允许当前席位决策，上一轮结束后才安排下一轮；重复单步请求合并处理。
- AI 超时、异常或非法决策自动托管；真人仅超时托管，非法输入不推进。托管叫分不叫、跟牌不出、领出打最小单牌，并记录原因。
- 暂停和停止会取消未完成的异步决策，迟到响应不推进牌局。传给决策方的状态是独立副本，出牌使用服务端持有的真实牌数据。
- 日志包含种子、席位、阶段、实际动作、托管来源与原因，可用 `replayJournal` 重建并校验每一步。

决策超时针对可异步取消的调用；同步 Bot 必须快速返回，JavaScript 主线程内的死循环无法被定时器抢占。未结束对局日志保存在内存，重启会清空；已完成并入账的日志保存在 SQLite，仍可导出 JSON。协议与恢复方式见 [调度文档](docs/SCHEDULER.md)。

房间最多保留 32 间（含关闭后等待回收的房间）。无观众且没有新动作的房间默认 30 分钟后关闭，关闭后默认 5 分钟删除，每分钟检查一次。观众离开不立即终止进行中的游戏；最后一位观众离开后从该时刻计算空闲时间。Agent 在对局开始前退出可补位，开始后退出则关闭该房并保留已有日志。进程退出会回收所有调度器与 SSE 连接。
